Pilih cara menjalankan

dua-duanya menjalankan aplikasi yang sama

Yang perlu ter-install: Docker Desktop saja. Go, PostgreSQL, dan Redis tidak perlu di-install.

  1. Buka terminal di folder project

    cd "I:\Fullstack Web Developer and Flutter Developer\rombong-api"

  2. Build dan jalankan semuanya

    docker compose up --build -d

    Docker membuat tiga container: api, postgres, redis. API baru start setelah PostgreSQL dan Redis lolos health check. Migration database jalan otomatis, dan akun admin dibuat: admin@example.com / Admin12345.

  3. Cek sudah hidup

    curl.exe http://localhost:8080/health

    Hasil yang benar: {"database":"up","redis":"up","status":"ok"}. Di PowerShell pakai curl.exe, karena curl di sana adalah alias untuk perintah lain.

  4. Coba API-nya

    Buka http://localhost:8080/docs di browser untuk Swagger UI. Base URL API: http://localhost:8080/api/v1.

  5. Perintah sehari-hari

    docker compose logs -f api     # lihat log API
docker compose ps              # status container
docker compose down            # matikan (data tetap tersimpan)
docker compose down -v         # matikan + hapus data database
Port bentrok? Kalau 5432, 6379, atau 8080 sudah dipakai aplikasi lain, ubah angka sebelah kiri di bagian ports pada docker-compose.yml, misalnya "8081:8080".
Yang perlu ter-install: Go 1.24+, PostgreSQL 13+, dan Redis (opsional: tanpa Redis API tetap jalan, hanya tanpa cache dan rate limit).

  1. Siapkan file konfigurasi

    copy .env.example .env      # Windows
cp .env.example .env        # macOS / Linux

    Buka .env, lalu isi minimal: JWT_SECRET (minimal 32 karakter), dan DB_USER / DB_PASSWORD sesuai PostgreSQL di laptopmu. Kalau JWT_SECRET kurang dari 32 karakter, aplikasi sengaja menolak jalan.

  2. Buat database

    createdb -U postgres ecommerce

    Atau lewat pgAdmin / DBeaver: buat database bernama ecommerce. Tabelnya tidak perlu dibuat manual.

  3. Jalankan

    go run ./cmd/api

    Saat start, aplikasi menjalankan migration (AUTO_MIGRATE=true), membuat admin dari ADMIN_EMAIL / ADMIN_PASSWORD, lalu listen di port 8080.

  4. Cek

    curl.exe http://localhost:8080/health

    Kalau Redis tidak jalan, hasilnya "status":"degraded". Itu normal; API tetap berfungsi.

  5. Build binary untuk produksi (opsional)

    go build -o bin/api ./cmd/api        # hasilnya satu file
go run ./cmd/api -migrate-only       # hanya jalankan migration lalu keluar
Di Windows biasanya tidak ada make. Semua perintah di Makefile bisa diganti dengan perintah go langsung seperti di atas.

  1. Unit test (tanpa database)

    go test ./...

    Tambahkan -race untuk mendeteksi data race. Di Windows, -race butuh compiler C (gcc); kalau belum ada, jalankan tanpa flag itu.

  2. Integration test (butuh PostgreSQL)

    Pakai PostgreSQL dari Docker (database ecommerce_test otomatis dibuat):

    docker compose up -d postgres
go test -tags integration ./tests/...

    Tanpa Docker: buat database ecommerce_test, lalu atur koneksinya lewat env var.

    createdb -U postgres ecommerce_test
# PowerShell
$env:TEST_DB_PASSWORD="passwordmu"; go test -tags integration ./tests/...
Integration test mengosongkan semua tabel di database test. Jangan arahkan ke database ecommerce yang berisi data penting.

Coba alur lengkap

setelah server jalan; pakai Swagger UI kalau tidak mau mengetik curl

  1. Login admin POST /auth/login → salin access_token
  2. Buat kategori POST /categories dengan header Authorization: Bearer <token admin>
  3. Buat produk POST /products berisi category_id dari langkah 2
  4. Daftar customer POST /auth/register, lalu POST /auth/login
  5. Masukkan ke cart POST /cart/items dengan token customer
  6. Checkout POST /orders (tanpa body)
  7. Bayar POST /payments dengan header Idempotency-Key berisi teks acak, lalu POST /payments/:id/simulate-success
  8. Cek GET /orders/:id → status PAID

Kenapa API ini ada?

API ini adalah backend toko online: semua aturan bisnis dan data ada di server, dan aplikasi apa pun (web React, Flutter, Android) cukup memanggil endpoint-nya. Frontend tidak menyimpan harga, stok, atau status pesanan sendiri.

Sebagai portfolio, e-commerce dipilih karena memaksa kita menyelesaikan masalah backend yang sungguhan, bukan sekadar CRUD:

  • Uang: harga tidak boleh dipercaya dari klien, total harus tepat, dan pembayaran tidak boleh terproses dua kali.
  • Konkurensi: banyak orang membeli barang terakhir di detik yang sama.
  • Keamanan: login, token, hak akses admin vs customer, data milik orang lain.
  • Performa: katalog dibaca jauh lebih sering daripada diubah, cocok untuk cache.

Itu semua adalah topik yang paling sering ditanyakan di interview backend.

Kenapa pakai Docker?

Tanpa Docker

  • Install Go, PostgreSQL, Redis satu per satu, versi bisa beda tiap laptop.
  • "Di laptop saya jalan kok" — tapi di server tidak.
  • Orang yang mau mencoba portfolio-mu harus setup 30 menit.
  • Database lokal tercampur dengan project lain.

Dengan Docker

  • Satu perintah docker compose up: API, PostgreSQL 16, Redis 7 langsung jalan.
  • Versi sama persis di laptop, CI, dan server, karena semuanya ditulis di Dockerfile dan docker-compose.yml.
  • Terisolasi: tiap project punya database sendiri, hapus bersih dengan docker compose down -v.
  • Siap produksi: image yang sama bisa langsung dipakai di Kubernetes / OpenShift.

Kenapa Dockerfile-nya multi-stage?

Stage 1: builder

Image golang:1.24-alpine yang besar (ada compiler Go) dipakai untuk go build. Stage ini dibuang setelah selesai.

Stage 2: runtime

Image alpine kecil, hanya berisi satu binary hasil build. Berjalan sebagai user non-root. Lebih kecil = lebih cepat di-deploy dan lebih sedikit celah keamanan.
